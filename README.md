## 💡 设计初衷

备考、减脂、学 AI、读书——这些目标分散在不同 App 里，每天在忙，却看不到趋势，也攒不下自己的数据。

**核心洞察**：把多个自我提升目标整合进一个随身、数据私有、可追踪的工作台，比用好几个 App 更容易坚持。

三个痛点：

1. **数据散落**：体重、打卡、学习进度各在各处，无法统一复盘。
2. **缺乏周期视角**：知道今天做了什么，不知道这周、这月有没有进步。
3. **内容不贴合**：通用 App 不关心你的「AI PM 转型路径」「乐刻周课表」「16+8 轻断食」。

## 🧭 设计思路与理念

1. **单文件即应用**：零依赖、零构建，一个 `index.html` 就是全部。部署简单、不易整体挂掉。
2. **数据归自己**：本地 `localStorage` 为主，可选 Gist / Supabase 同步；云端不含 Token / 密钥，可选口令加密。
3. **单日克制、周期复盘**：每天任务压到约 30 分钟，靠热力图与周复盘提供长期视角。
4. **内容为王、贴合个人**：术语库按 AI PM 定制，学习计划按个人 8 月计划，饮食 / 训练按乐刻课表。
5. **防丢失优先**：关键写入带时间戳，多端合并按 last-write-wins。

## ⚙️ 核心机制

| 机制   | 作用                             | 场景              |
| ---- | ------------------------------ | --------------- |
| 每日快照 | 每天 0 点按日期种子分配固定批次，当天不跳动        | AI 术语卡轮换、学习计划展示 |
| 顺序解锁 | 完成一项才开下一项，按日期匹配                | 24 天 AI 转型计划    |
| 复习门禁 | 每张术语卡刷满 3 遍才解锁「已掌握」            | 首轮学完后的复习期       |
| 自动计算 | BMI / 基础代谢按个人信息自动算，可手动覆盖       | 体重录入            |
| 模糊搜索 | 本地食物库 200+ 条、运动库，输入即联想         | 饮食 / 运动记录       |
| 防盲合并 | 按记录 `ts` 做 last-write-wins     | 多端 Gist 同步      |
| 离线缓存 | Service Worker 导航强制刷新，版本递增强制更新 | PWA 离线可用        |

## 🚀 如何使用

### 快速开始

1. 打开线上地址：`https://peiky6.github.io/workbench/`（首次需联网加载，之后可离线）。
2. 手机浏览器「添加到主屏幕」，即得一个类原生 App。

> [!NOTE]  
> 数据默认只存在你当前浏览器。换设备 / 清缓存前，请在「设置 → 数据同步」配置 Gist 或 Supabase 做备份。

### 配置云同步

1. GitHub 新建一个 Gist（任意文件名，如 `workbench.json`）。
2. 生成带 `gist` 权限的 Personal Access Token。
3. 在「设置 → 数据同步」粘贴 Gist ID 与 Token，保存后自动上传；打开 App 自动下载合并。

> [!IMPORTANT]  
> 同步数据**不包含** Token / 密钥（`settings` 字段在上传前被剔除）。开启「本地口令加密」后，云端存放的是 AES 密文，口令不离开本地。

### 示例：记录一天

1. 早晨：首页看「今日待办」→ 体重管理套用训练日饮食计划 → 记录体重（自动算 BMI / BMR）。
2. 通勤：雅思菜单点选 1–2 项打卡 → AI 术语卡刷 3 遍。
3. 傍晚 17:00：吃完晚餐（16+8）→ 按乐刻课表训练打卡。
4. 晚间：本周复盘 + 新闻阅读 + 学习计划推进。

## 📦 技术栈

- **语言**：HTML / CSS / JavaScript（全部内嵌于单文件，无框架）
- **离线**：PWA（`manifest.webmanifest` + `sw.js`，缓存名 v8）
- **部署**：GitHub Pages（静态托管，无后端）
- **测试**：Node `smoke.cjs`（抽取脚本跑 `node --check` + 关键函数校验）

## 📁 目录结构

```text
workbench/
├── index.html            # 应用主文件（全部 HTML/CSS/JS，约 250KB）
├── sw.js                 # Service Worker：离线缓存与版本更新（v8）
├── manifest.webmanifest  # PWA 清单
├── smoke.cjs             # 固化冒烟测试，每次改动回归
├── _p.cjs                # 部署脚本（推送到 GitHub Pages）
├── supabase_setup.js     # Supabase 同步建表脚本
├── icon.svg / *.png      # 应用图标（含 maskable）
├── .nojekyll             # 禁用 GitHub Pages 的 Jekyll 处理
└── README.md             # 本文档
```

> [!WARNING]  
> 保持单文件是刻意的架构选择。如需拆分，优先采用「无构建多文件 `<script src>`」方案，而非引入打包工具，以免把线上弄挂。
